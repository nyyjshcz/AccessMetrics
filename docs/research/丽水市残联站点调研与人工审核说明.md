### 先看哪些问题

- 丽水市政府门户样本：最常见的是 `color-contrast`、`aria-prohibited-attr`、`html-has-lang`、`link-name`、`image-alt`、`region`。
- 浙江省残联样本：最常见的是 `color-contrast`、`aria-prohibited-attr`、`aria-roles`、`aria-valid-attr`、`image-alt`、`region`。
- 丽水市公共数据平台：主要看到 `color-contrast`、`bypass`、`landmark-one-main`、`link-name`、`meta-viewport`、`page-has-heading-one`、`region`。

这些是“自动扫描优先级”，不是人工最终结论。比如 `color-contrast` 需要确认实际前景/背景、字体大小和状态；`link-name` 需要看链接对用户是否有足够语义；`aria-*` 需要看组件实际角色和键盘行为。

## 人工审核到底怎么做

### 现在可以做的探索性理解

1. 打开某个结果页的“问题详情与筛选”，先按 `result_type=incomplete` 看需要人工判断的项目，再按 `critical/serious` 看自动失败的高影响项目。
2. 每个问题查看页面 URL、规则帮助、节点定位、清理后的 HTML 片段和失败原因；不要只看分数。
3. 如果只是理解某个节点，可以用 reviewer 登录后打开 `/review/<runId>` 做 ad-hoc 记录，选择“确认问题 / 不是问题 / 不确定”，并写一句理由。
4. 这些 ad-hoc 记录只服务于当前理解，**不能代替正式 R2/R3，也不能外推为总体准确率**。

### 正式研究审核的顺序

1. 两位真人负责人先共同确定研究协议、样本框、纳入/排除理由、页面上限、采集时间窗、评分版本和标准来源，分别提交 R1 receipt。
2. 把上表中要纳入的 URL 写入正式 `research/sample-frame.csv`，为每个 URL 写清楚官方依据和纳入理由；公开可访问不等于已经获得正式研究许可。
3. 完成 campaign 扫描并导出 source export，冻结 source manifest 和 population digest。
4. 服务端按固定的 `manual-review-sampler-v1` 生成抽样 batch。抽样不是人工挑“看起来典型”的页面，而是由固定种子和分层规则确定。
5. 计算机负责人和数学负责人分别用自己的 reviewer token 登录 `/review/login`，在 `/admin/reviews/<batchId>`（或对应 reviewer 页面）独立审核同一批样本。双方在提交前看不到对方 verdict。
6. 每条样本只能选三种结果：`confirmed`（确认是问题）、`not_an_issue`（不是问题）、`uncertain`（信息不足/无法判断），并写可复核的理由。误录只能通过 revision 更正，不能覆盖历史记录。
7. 双方意见一致就记录 agreement；出现分歧时，提交 adjudication，由指定 reviewer 审核并批准。只有 approved adjudication 才能成为最终结论。
8. 冻结 review set、adjudication set 和 hash，提交 R3；之后才进入 R4 报告候选核对，最终由 `pnpm project:resume` 继续研究链。
