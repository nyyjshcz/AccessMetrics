# 安全边界

> **谁需要读：部署负责人。是否必读：部署路径必读，其他角色按需查阅。** 本页只记录当前代码真正执行的访问、扫描目标、密钥和报告发布边界。

## 访问密钥

管理员密钥允许创建扫描、配置 AI、处理 incomplete、发布报告和删除未发布的终态任务。访客密钥只能读取已发布报告。`SESSION_SECRET` 是服务器内部密钥，用于签名会话 Cookie 和加密保存的 Provider Key，不交给使用者。

密钥只从环境变量或 Docker secret 文件读取。管理员和访客密钥必须不同且至少 16 个字符；不要提交到 Git、日志或公开导出目录。

## 请求与扫描目标

带 `Origin` 的写请求必须与 `APP_BASE_URL` 同源。登录请求也必须同源。扫描目标只接受 HTTP/HTTPS，不允许凭据 URL、localhost、私网、环回、云元数据主机名和其他保留地址。爬虫默认限制在同源页面，跨源重定向会被拒绝。

生产扫描 Worker 必须通过显式 `EGRESS_PROXY_URL` 出站。Web 为 PDF 渲染可以使用独立的浏览器出站路径，不能用它绕过扫描 Worker 的代理要求。

## 其他运行保护

新建扫描接口有进程内限速，并接受 `idempotency-key` 来避免用户重复提交同一个任务。这只能减少当前进程里的重复请求，不能代替网络层的限流。

登录会按客户端做短时间尝试限速。登录成功后，服务器写入 7 天有效的 `HttpOnly`、`SameSite=Lax` Cookie；生产环境还会启用 `Secure`。响应会带常见的浏览器安全头。AI Provider 请求不会自动跟随重定向，日志会隐藏常见的凭据字段。

## 报告与数据

已发布运行只读。公开报告只允许读取已完成且不处于活动 AI 批处理的扫描。私有证据、数据库、人工备注和 Provider Key 不应挂载为公开资源。

这些措施不能替代网络隔离、容器沙箱、密钥轮换或对目标网站的授权。完整部署步骤见 [部署说明](./ops/deployment.md)。
