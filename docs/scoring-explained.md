# 评分解释：怎样读懂 0 到 100 分

> **谁需要读：教授、项目评审和需要解释报告的人。是否必读：仅评审路径必读。** 数学负责人以[数学负责人完整理解指南](./数学负责人完整理解指南.md)为主，不需要重复读本文。

## 先说结论

AccessCheck 的分数是一次扫描中、**具备 WCAG A/AA 计分资格（已映射至 WCAG A 或 AA、目录标记为可计分，且只对 `pass` 或 `violation` 节点计入）且已经可以判为通过或问题的节点机会**的严重程度加权结果。它用于定位和比较本次扫描范围内的风险，**不是**全站覆盖率、人工审计结论或 WCAG 合规认证。

## 计数单位

| 单位 | 是什么 | 容易误读成什么 |
| --- | --- | --- |
| 页面 | 一次任务实际发现或尝试扫描的 URL。 | 随机抽样样本或全站全部页面。 |
| 规则结果 | 一个页面上一条 axe 规则的结果行。 | 一个问题元素。 |
| 节点 | 被规则命中的页面元素数量。 | 规则行数。 |
| 计分机会 | 能判为 pass 或 violation 的 eligible 节点。 | DOM 元素总数。 |

`rule_results.node_count` 保存所有结果类型的真实节点数。`result_nodes` 只保存 violation 和 incomplete 的详细证据，因此不能用它的行数统计 pass 或 inapplicable。

这里的 `eligible` 是上述计分资格的英文简称。

## 主公式

令 `E` 为本次扫描中所有已判定、具备计分资格的节点机会，`N = |E|`。一个通过节点权重为 0；问题节点按 axe 严重程度赋权：

| 严重程度 | 权重 |
| --- | ---: |
| critical | 4 |
| serious | 3 |
| moderate | 2 |
| minor | 1 |

这里的 impact 严重度来自 axe 的结果字段，不是 WCAG 的 A、AA、AAA 等级；WCAG 等级只参与计分资格映射。

总分为：

```text
S = 100 × (4N − Σwᵢ) / (4N)
```

例如，8 个 pass、1 个 serious、1 个 moderate：`N = 10`，`Σwᵢ = 5`，所以 `S = 87.5`。实现以整数分子、分母计算，最后才按一位小数做一次半进位舍入；不要用已经显示的单页小数再平均。

若没有任何可计分机会，分数应理解为 **N/A（无可计算数据）**，不是 0 分或 100 分。

## 为什么不是“页面平均分”

网站总分将本次 run 的所有计分机会合并后计算：节点多的页面自然有更大权重。它不是各页面显示分数的简单平均，也不是四项原则显示分数的平均。

例如，一页有 1 个节点，另一页有 99 个节点，后者对池化总分的影响会更大。

一个节点可映射到多个 WCAG 原则：它会分别出现在相关原则的诊断子分数中，但在总分中只计一次。因此四项原则的机会数相加可以大于总分机会数，这是设计使然。

## 哪些结果进入分数

| 原始结果 | 原始分数处理 | 原因 |
| --- | --- | --- |
| pass | 计入，权重 0 | 自动检查得到通过结论。 |
| violation | 计入，按严重程度扣分 | 自动检查得到问题结论。 |
| incomplete | 不计入 | 自动规则尚不能可靠判断。 |
| inapplicable | 不计入 | 规则对该节点不适用。 |

即使是 violation，也只有规则目录映射为 WCAG A 或 AA 并标记为可计分时才进入分数。AAA-only、best-practice、未知或未映射规则仍在证据中可见，但不会悄悄影响分数。

## 原始分数与复核后分数

系统同时展示两个口径：

- **原始评分（raw score）**：只根据原始 pass 与 violation 计算；incomplete 不直接扣分。
- **复核后评分（effective score）**：如果原始 incomplete 已获得有效结论，则 `problem` 按问题处理、`not_problem` 按通过处理，`uncertain` 仍不计分。

首次出现的 `problem`、`not_problem`、`uncertain` 是复核结论值，不是新的扫描结果；它们只影响 effective score，不改原始扫描结果。人工结论始终优先于 AI，AI 结论又优先于原始未解决 incomplete。无论哪种复核，原始 axe 规则结果和节点证据都不会被改写。

这也意味着：AI 处理进度、incomplete 覆盖率和最终分数是三种不同数字。覆盖率表示有多少不确定项被处理，不能代表 AI 准确率或网站无障碍质量。

## 用于展示时的边界

- 可以说：“在本次实际扫描到的页面和符合资格的节点中，按当前严重程度权重得到 X 分。”
- 不应说：“该网站有 X% 已经 WCAG 合规”或“该网站通过了认证”。
- 应先看扫描覆盖范围、页面失败和 incomplete 数量，再讨论分数。
