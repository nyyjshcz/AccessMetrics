# 常见问答

> **历史参考。** 本文的角色、路径或命令可能已过时；当前事实以 [文档地图](../../../README.md) 为准。

**为什么不承诺一千亿行？** 项目规模是 10–20 个网站、约 100–300 个成功页面；SQLite 保证的是这个规模的事务、外键、恢复和追溯。

**axe 的 serious 是什么？** 它是 axe 对结果的原始影响级别；本项目透明地把它映射为 3 倍缺陷权重，原值和映射来源都保存。

**为什么 incomplete 不扣分？** 它表示需要人工或运行时上下文核验，不能伪装成确定失败；数量和覆盖仍披露。

## 进一步问题

**1. 系统到底扫描什么？** 只扫描公开 HTTP/HTTPS HTML 页面，不登录、不绕验证码、不提交表单。

**2. 为什么限制每站页数？** 研究协议要让每个站点的机会数可比，也控制对外部网站的访问压力。

**3. 谁能启动扫描？** 只有 admin 会话；匿名访客只能读取已发布结果。

**4. reviewer token 和 admin token 有什么不同？** reviewer token 绑定计算机或数学角色，不能由请求体自报；admin 不能代替审核。

**5. CSRF 和 Origin 为什么都要？** CSRF 防止跨站伪造请求，Origin 再限制请求必须来自系统自己的来源。

**6. Idempotency-Key 解决什么问题？** 网络重试时复用同一个键只得到同一个任务，不会重复创建扫描。

**7. Worker 挂掉会怎样？** lease 过期后其他 Worker 可接管，已完成页有唯一键保护，不重复扫描。

**8. 为什么不保存完整 HTML？** 完整正文可能包含个人数据；只保存清理且限长的节点片段和 hash。

**9. axe 的四组结果是什么？** passes、violations、incomplete、inapplicable；四组都保存，只有确定的 opportunity 进入评分分母。

**10. serious 是法律结论吗？** 不是。它只是 axe 的影响级别，本项目另保存映射来源和权重配置。

**11. 一个规则有两个原则怎么办？** 总分机会只计一次，四项分分别按原则贡献，并在详情展示多原则映射。

**12. 为什么 violation 节点优先使用 node impact？** 节点的实际影响可能比规则级默认值更具体；两者为空才使用固定回退权重，并记录来源。

**13. 分数为什么保留精确分子分母？** 这样 TypeScript、Python 和重复导出都能重算同一未舍入结果，展示值只在最后 half-up 到一位小数。

**14. 页面分数如何合成网站分数？** 汇总页面的整数分子和分母后再计算，而不是先平均已舍入的小数。

**15. 0 分代表什么？** 在模型定义下所有可评分机会都失败，不代表网站“完全不可访问”。

**16. N/A 代表什么？** 没有可评分机会，不能把它当作 0 分或 100 分。

**17. WCAG 标签怎么来的？** 由 axe tags 解析并和冻结的 WCAG 2.2 成功标准表比对，未知未来编号不会被静默当成已知条款。

**18. 4.1.1 为什么不评分？** WCAG 2.2 已移除它；目录保留 removed 记录，但评分机会为零。

**19. frame 怎么处理？** 顶层、同源和跨源 frame 分开尝试；失败 frame 记覆盖限制，不能当作通过。

**20. SSRF 如何防？** URL、DNS 返回地址、重定向和页面子资源都经过同一个 DestinationPolicy；私网和 metadata 地址拒绝。

**21. 为什么 localhost fixture 仍能测试？** 只有测试显式注入 allowPrivateAddresses，生产没有该开关。

**22. robots.txt 会怎样？** 尊重站点的公开 robots 规则；被禁止的页面记录失败原因，不伪造成功。

**23. 失败页面要不要删除？** 不删除，失败原因、状态和尝试次数会进入 attempt log 和报告限制。

**24. source export 和 final export 区别？** source 是没有人工审核的冻结机器结果；final 还绑定 review freeze、R4 本地化和 outcome digest。

**25. manifest 的作用是什么？** 它列出文件路径、大小和 SHA-256，让报告、导出和公开 ZIP 可追溯到同一字节。

**26. 为什么不能把 source 改成 final？** source 是只读证据；final 必须新建 revision，不能回写 source 或改变历史。

**27. 人工抽查会得到什么结论？** 只能描述抽样节点的复核数量、一致与分歧，不能外推成 axe 的总体准确率。

**28. R1–R5 是谁完成的？** 两位真人负责人使用各自 role-bound reviewer 会话完成；AI 不能代填姓名、结论、签字或已掌握。

**29. R5 为什么需要共同 bundle？** 两位负责人必须在同一 rcCommit 上完成相同六份 artifact，服务端计算共同 hash，防止各自提交不同材料。

**30. Docker 没装能说上线了吗？** 不能。没有 Docker、服务器、域名、密钥和固定镜像 digest，只能说本地代码和静态模板已验证。

**31. SQLite 能承诺一千亿行吗？** 不能。本项目保证的是 10–20 个站点、约 100–300 个成功页面的研究规模；一千亿行需要另立分布式系统。

**32. 为什么不公开研究 ZIP？** 只有 release_ready、隐私/许可批准、R5/full hash、通过的 validation/build attestation 全部绑定时才可公开。

**33. 私有证据怎么备份？** 数据库可以单独备份；私有 evidence 使用外部提供的 32-byte key 做 AES-256-GCM 加密，密钥不进仓库。

**34. 如何恢复正式研究？** 补齐[旧版外部输入说明](../validation/EXTERNAL_INPUTS.md)中的真实输入后运行 `pnpm project:resume`，它先验证 hash 和质量门，缺项仍停在等待状态。

**35. 报告能否写“符合 WCAG”？** 不能。只能说自动检查项的结果，并明确不等同完整人工审计或官方认证。
