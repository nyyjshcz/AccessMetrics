### 先看哪些问题

- 丽水市政府门户样本：最常见的是 `color-contrast`、`aria-prohibited-attr`、`html-has-lang`、`link-name`、`image-alt`、`region`。
- 浙江省残联样本：最常见的是 `color-contrast`、`aria-prohibited-attr`、`aria-roles`、`aria-valid-attr`、`image-alt`、`region`。
- 丽水市公共数据平台：主要看到 `color-contrast`、`bypass`、`landmark-one-main`、`link-name`、`meta-viewport`、`page-has-heading-one`、`region`。

## 人工审核到底怎么做

### 先把“688 条”理解对

当前丽水市政府“市残联”栏目这一次扫描共有：

- 839 个工具可直接判定的失败节点；
- 688 个需要结合语境判断的 `incomplete` 节点；
- 合计 1527 个可追溯的自动问题证据，归并为 140 个“页面 × 规则”问题组；其中 688 个 `incomplete` 先归为 30 个问题组。

所以，**688 不是 688 项必须逐条完成的人工待办**。例如 `color-contrast` 在同一页面可能出现一百多个类似元素；人先核对少量有代表性的节点，再在需要时查看整组或任意一个具体节点。

### 日常核对：现在就能做，也能审核任意一条数据

1. 打开某个扫描结果页，点击“人工审核与数据核对”中的“进入人工审核工作台”。主入口是 `/scans/<runId>/review`。
2. 工作台先显示全量证据、`incomplete` 问题组数量和当前最多 12 个代表样本。这个队列优先覆盖需要语境判断和高影响问题；每完成一个问题组的首条日常注记，系统会自动补入下一个还未覆盖的问题组。因此它是持续的小队列，不是做完 12 条就中断，也不是把其它数据藏起来。
3. 对一个代表样本，先打开真实页面，再看“你要看什么”、元素定位、扫描器保存的 HTML 片段和 axe 规则说明。选择“确认存在问题 / 当前页面不构成问题 / 暂不确定”，并写至少 5 个字的判断理由。
4. 如果你需要审核的不是这 12 个样本：在“问题列表”展开任意问题组，里面的每一个节点都有“审核这个节点”入口。点击后会把该节点带回同一个工作台，显示完整证据并允许独立提交。也就是说，所有 `violation` 和 `incomplete` 原始节点都能审核。
5. 保存后，界面会立即更新：该节点的日常人工注记、你已查看多少节点、已有多少问题组留下首条日常注记，以及确认/不成立/不确定的数量。一个节点的判断**不会**把同组其它节点自动标成已审核；提交按钮会在保存期间锁住，避免重复写入。正式双人审核的数据保留在独立的正式 batch 中，避免在盲审阶段泄露另一位 reviewer 的判断。
6. 日常核对不会修改 axe 原始证据或自动分数。它用于理解、发现误报风险和记录可复核的人工观察，**不能代替正式 R2/R3，也不能外推为工具总体准确率**。

### 正式研究审核：只做固定小样本，而不是审完六百多条

1. 两位真人负责人先共同确定研究协议、样本框、纳入/排除理由、页面上限、采集时间窗、评分版本和标准来源，分别提交 R1 receipt。
2. 完成 campaign 扫描并导出 source export，冻结 source manifest 和 population digest。
3. 服务端按固定的 `manual-review-sampler-v1` 从全部自动问题证据中抽取**最多 40 个**节点；不是人工挑选，也不是把 688 个 `incomplete` 全部派给人。
4. 扫描结果页的“正式研究审核状态”会明确显示现在卡在 R1、来源冻结、固定抽样、独立审核还是冻结。当前没有真实 R1 时，它只显示等待原因，不会创建假 batch。固定 batch 真正生成后，计算机负责人和数学/数据负责人分别用自己的 reviewer token 登录 `/review/login`，再从状态卡进入自己的 `/admin/reviews/<batchId>`。两位 reviewer 各完成最多 40 条，合计最多 80 次独立判断。
5. 正式页面只显示“我的进度、总样本数和剩余数”。它**故意不显示**另一位 reviewer 的完成数、答案、一致率或待裁决数，避免影响独立判断；每条必须写可复核理由。
6. 两位正式审核都完成后，系统才允许对真实分歧提出裁决；提出人和批准人必须不同。只有 approved adjudication 才能进入 review freeze 和 hash。正式审核、裁决和冻结数据不会混入日常工作台、普通 run 导出或公开报告。

日常核对与正式研究是两层不同的流程：前者让你方便理解和审阅全部数据，后者让研究结论在可控样本量、双人独立和可追溯条件下成立。

- 每个站点的正式纳入理由、公开依据/许可、替补顺序和采集时间窗；
- 两位 reviewer 的真人身份和各自 token（不能把 token 写入 Git）；
- R1 要冻结的协议、样本框、评分公式、WCAG 2.2 / GB/T 37668-2019 方法边界；
- 两位 reviewer 完成 R2/R3 的真实人工记录和分歧裁决；
- R4/R5 及生产环境的真人证据、渲染器、服务器、域名、代理和密钥。
