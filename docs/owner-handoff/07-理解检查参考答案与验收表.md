# 理解检查参考答案与验收表

必须能解释六件事：URL SSRF 防护、axe 四类结果、WCAG 标签映射、评分公式、Worker 恢复、export-id/manifest 追溯。任一项错误都要复习重测，不能用总分抵消。实际得分和确认由本人写入 R5 私有证据。

## 参考答案要点

| 主题     | 至少应说清楚                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------- |
| SSRF     | URL/DNS/重定向/子资源共用策略；拒绝私网、localhost、metadata、凭据和危险协议；测试白名单只在 fixture 注入 |
| axe 四类 | passes、violations、incomplete、inapplicable 都保存；incomplete 不冒充确定失败                            |
| WCAG     | tags 解析到冻结成功标准；原则/等级来自目录；未知编号不静默猜测，4.1.1 removed 不评分                      |
| 评分     | 整数分子分母；node impact → rule impact → 固定回退；多原则总分只计一次；最后 half-up 一位小数             |
| Worker   | queued→leased→running→terminal；heartbeat/lease 过期恢复；唯一键保护完成页不重扫；取消和部分失败保留事实  |
| 追溯     | export-id、manifest hash、run/page/rule/node 和报告 hash 可相互追溯；source 不被 final 回写               |

R5 还必须完成固定六项练习、六类主题理解检查和 A–E 交接确认；通过条件由服务端根据提交内容计算，客户端不能上传 `passed=true`、`confirmed=true` 或自选 hash。

## 服务端评分规则

服务端把每个主题拆成 5 个固定要点，每个要点 20 分；提交内容只按固定关键词组命中计分，答案不能自行声明通过。每个主题的 5 个要点必须全部命中，且六个主题平均分至少 80 分，才会写入 `passed: true`。服务端同时写入 `rubricVersion`、`questionSetHash`、逐主题得分和命中点数；以后如果题目或评分规则变化，必须产生新的题集 hash，旧 receipt 不会被重新解释。

六个主题的固定要点分别是：SSRF 的 URL/DNS、重定向/子资源、私网/localhost/metadata、凭据/危险协议、fixture 白名单；axe 的四类结果、保存、incomplete 不确定、violation 失败、inapplicable 不适用；WCAG 的 tags 解析、冻结成功标准、目录中的原则/等级、未知不猜、4.1.1 移除不评分；评分的整数分子分母、node→rule 影响级别、回退、多原则只计一次、half-up 一位小数；Worker 的状态链、heartbeat/lease 恢复、唯一键、取消和部分失败事实、崩溃重启；追溯的 export-id、manifest hash、run/page/rule/node、报告 hash、source 不被 final 覆盖。
