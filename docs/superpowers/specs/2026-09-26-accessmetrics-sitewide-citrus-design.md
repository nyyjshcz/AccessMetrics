# AccessMetrics 全站视觉统一与报告导出设计

## 目标

将 AccessMetrics 的全部应用内页面统一为用户选定的 C「柑橘自然感」；所有按钮、表单、导航、状态和反馈使用同一套视觉规则。独立导出的 HTML 与 PDF 则共用清爽、易读、适合打印的报告样式。视觉调整不得改变登录角色、路由、扫描、复核、AI 任务、发布和导出行为。

受众包括未登录访客、招生官体验者以及管理员。成功标准是：不同页面一眼属于同一产品，主要操作层次一致；高密度工作页仍便于定位状态和下一步；HTML 与 PDF 的报告正文在结构和风格上保持一致；桌面与窄屏均可读、可操作。

## 设计方向

### 品牌与视觉语言

以现有 C 版预览为基准：温暖的纸感底色、柑橘/鼠尾草绿的大面积柔和色块、深森林绿文字与主操作，以及克制的珊瑚色问题标注。应用页面不把登录页的左右分栏机械复制到各路由；改为共享轻量顶栏和内容网格，并按页面任务使用强调区、纸面内容区和数据列表。

基础色值取自已选 C 版：

| 语义 | 色值 | 用途 |
|---|---|---|
| 墨绿文字 | #1d3931 | 标题与主要正文 |
| 森林绿 | #1d5145 | 品牌、主按钮、活动导航 |
| 温暖画布 | #e9e7e0 | 应用背景 |
| 纸面 | #f8f6e7 | 内容表面和表单 |
| 柑橘浅绿 | #e9edb8 | 少量关键介绍/进度强调 |
| 鼠尾草绿 | #d8e2ad | 次级强调面 |
| 金色 | #f4c578 | 证据或关键数据标记 |
| 珊瑚色 | #bf563f | 问题注释；不作为大面积底色 |

采用 C 预览的无衬线字感和系统字体回退，不依赖远程字体。主要内容保持高对比；状态含义除颜色外还要有文字标签/图标。用一处真实的“网页证据与问题标记”作为产品视觉记忆点，其他装饰从简。

### 应用壳与按钮

共享顶栏继续按角色显示导航，保留中英文切换、登录状态和退出；调整间距、当前页提示和窄屏换行/收纳，管理员与访客权限边界不变。页面标题、说明、主动作、内容区采用一致的间距和层级；AI Worker 等高密度页面优先使用清晰分组、表格和状态摘要，不堆叠大卡片。

全站原生按钮与按钮样式链接统一到四种语义：森林绿主操作、纸面/描边次操作、低强调文本操作、珊瑚/深红危险操作。统一尺寸、圆角、间距、焦点环、悬停、禁用和提交中状态；每个操作组突出一个主操作。保留原生 button/link/form 语义和所有现有 accessible name、aria-busy、提交方式及确认行为，不以样式重写交互。

### 页面覆盖

以下全部 12 个页面纳入改造：

- 公开入口：/login、/team。
- 工作台与目录：/、/scans、/reports。
- 扫描流程：/scans/new、/scans/jobs/[jobId]、/scans/[runId]、/scans/[runId]/review。
- 报告屏幕页：/reports/[runId]。
- AI 管理：/settings/ai、/settings/ai/worker。

页面内容结构服从任务：新建扫描突出表单与验证；任务详情突出进度、错误和下一步；复核页突出待办、证据、结论；报告库突出查找与状态；AI 配置和 Worker 监控突出当前状态、用量与危险动作；团队和登录入口保留可信、温暖的介绍感。屏幕上的报告详情属于应用页面，采用 C 风格。

## 导出的 HTML 与 PDF

HTML 和 PDF 共用 ReportDocument 的报告内容、章节顺序和一套独立的清爽报告样式：白/纸色背景、深色正文、森林绿标题与少量珊瑚证据标记；不包含应用顶栏、身份导航、发布/删除等工作台操作，也不使用大面积装饰背景、屏幕阴影或重复卡片。导出样式必须内嵌，使 HTML 可独立查看。

PDF 继续从同一 HTML 文档经 Playwright 打印生成，A4 排版及页眉/页码与 HTML 报告视觉协调。标题与正文避免分页拆开，表格行和证据块尽量完整；被折叠的报告细节仍须进入 PDF。HTML 现有语言切换作为轻量文档工具保留，并在打印样式中隐藏；它不改变报告正文的 HTML/PDF 同风格要求。

屏幕报告页面可以保留应用工作台操作区，但操作区与报告本体应视觉分明；导出内容不能泄漏或夹带仅供管理员使用的导航或操作控件。

## 实施边界与兼容性

- 复用现有 Next.js App Router、原生控件、页面类名和 ReportDocument；不引入 UI 框架或字体依赖。
- 将语义颜色与按钮规则集中维护，并清理互相覆盖的页面按钮样式；仅在能降低实际冲突时拆分样式文件，不做与本次目标无关的全盘 CSS 重构。
- 全站样式继续由应用全局样式负责；报告 HTML/PDF 使用独立、自包含的样式源，避免应用全局 CSS 污染独立导出。
- 不修改 API、数据库、权限、扫描和 AI Worker 生命周期，不改变报告数据或删除/发布行为。
- 保留管理员/访客导航差异、中英文切换、登录介绍和已有导出语言工具。

## 验收

1. 12 个应用路由及所有可见按钮均采用统一的 C 语义视觉、响应式间距和完整交互状态；窄屏无横向溢出，键盘焦点清晰。
2. 现有角色、路由、扫描、复核、AI 管理、发布/撤下和下载功能的行为测试继续通过。
3. HTML 与 PDF 使用相同的报告正文、顺序、色彩/排版规则；HTML 单独打开正常，打印控件不进入 PDF。
4. 真实生成 PDF 验证 A4 分页、表格、证据和展开细节；不能只用 mock 通过接口测试代替。
5. 在本地 Docker 完成应用构建、关键工作流和导出验证后，才进入 NAS 发布步骤；本设计本身不执行部署。
