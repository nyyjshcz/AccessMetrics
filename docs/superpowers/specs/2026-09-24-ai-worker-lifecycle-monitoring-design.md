# AI Worker 生命周期与费用监控设计

## 目标

防止 AI 复核队列脱离用户看到的扫描任务长期运行或无限重试，并让管理员能直接确认 Worker 正在处理什么、是否暂停以及产生了多少服务商报告的用量。页面刷新只重新读取状态，不创建、恢复或复制任务。

## 已确认的生命周期规则

- **删除扫描任务：** 同一扫描运行的所有 AI 批次和队列项一并删除，不论其状态是排队、运行、暂停、失败还是已完成。先持久化取消信号，再删除扫描关联数据；Worker 必须在发起请求前复核任务仍存在且有效。已经发出的请求尽快中止。非任务型的请求审计只能保留去标识后的状态、时间和用量，不能留下可恢复的 AI 批次或任务关联。
- **修改、停用或删除模型配置：** 取消该配置快照下所有非终态批次，清理未处理与失败队列，不自动迁移到新配置。管理员显式开始新复核时才用新配置创建批次。已完成的 AI 判断、人工复核和报告保留。
- **切换扫描的模型并再次开始：** 取消同一扫描下不匹配新选择的非终态批次及其未处理队列，再创建唯一的新活动批次；不可把旧模型快照的工作误当作新模型任务。
- **手动暂停：** 立即停止领取并请求中止在途调用；批次保持 `paused`，未处理项保留为 `queued` 但不计入活动队列，只允许在扫描与模型配置快照仍有效时由管理员显式恢复。中止确认后清除该项的运行租约。配置变化或源扫描删除会使其转为取消，不能恢复。
- 每个扫描至多一个可领取的 AI 批次。`queued/running` 才是活动队列；暂停和取消记录必须单独统计，不能再汇总成“排队中”。

## 实现方案

保留现有 SQLite 任务队列和独立 AI Worker，增加持久化的单次 API 调用记录。调用记录包括 Worker/槽位、批次和项目标识、模型配置快照名称、开始/结束时间、尝试序号、状态、HTTP 状态/脱敏错误码，以及服务商返回时的 prompt/completion/total tokens 和费用。不得保存 API key、请求提示词、目标页面内容或完整响应。删除源扫描时删除全部批次和项目行，并从非可执行的用量审计记录中清除 job/run/batch/item 标识，只保留模型、时间、状态、脱敏错误和服务商返回的用量。

Worker 在调用前再次验证扫描、批次、模型配置快照及取消状态；请求使用 `AbortController`。Worker 与 Web 容器通过共享数据库的持久化取消状态协作，Worker 最多每秒检查一次在途请求，目标是在 2 秒内停止后续工作并中止网络请求。页面显示“取消中”直到 Worker 确认中止或请求结束。若服务商已接收请求，客户端中止不能保证服务商停止计费或退款，界面应明确这一限制。

所有错误类型都受统一自动尝试上限约束：每个项目每个显式复核周期最多 3 次 API 调用（首次加最多两次自动重试）。仅可重试的错误使用有上限的指数退避；429 遵从 `Retry-After`。达到上限后标为失败，不再自动重排。管理员显式重试会显示受影响数量并开始一个新的、同样受上限约束的尝试周期。

增加管理员专用 AI Worker 监控页及只读状态 API。页面显示 Worker 在线/空闲/过期状态、当前调用对应的扫描、模型、批次、槽位、已运行时间和尝试次数；活动、暂停、取消及失败数量分别展示；另列近期成功/失败请求、Token 与服务商报告费用。服务商不返回某项用量时显示“未知”，不按模型标价推算。页面轮询只读取状态，不触发任务。现有 `admin` 权限保护页面和 API，响应中不包含密钥或请求内容。

## 主要改动边界

- 队列和 Worker：`src/lib/ai-overlay.ts`、`src/worker/ai.ts`、`src/lib/repositories.ts`。
- 持久化：`src/lib/db.ts` 新增迁移及 API 调用记录/取消状态。
- 删除和配置变更：扫描删除 API、AI provider 写入/删除 API、批次暂停/恢复/重试 API。
- 监控：新增管理员页面与只读 API；现有 AI 设置页提供入口。中英文界面都应覆盖。
- 保持扫描评分、原始规则结果、报告结构和现有 API Key 配置方式不变。

## 验收标准

1. 删除扫描后，其所有 AI 批次和项目记录均不存在，活动调用尽快中止，之后无法恢复或重试；其他扫描与报告不受影响。
2. 修改/停用/删除模型配置会取消并清理该旧配置下的所有非终态队列；已完成判断保留，新模型不会静默接管旧任务。
3. 手动暂停立即停止领取并中止活动请求；刷新/重开监控页不会恢复任务。
4. 任意持续性瞬时错误不可能超过每项目每周期 3 次自动 API 调用；429 退避期间不重复发送请求。
5. 监控页能区分当前 API 调用、空闲 Worker、暂停队列、取消/失败状态，并显示实际可获得的 Token/费用；不会泄漏 key、提示词或页面内容。
6. 聚焦集成测试覆盖删除、配置变更、暂停、中止竞态、重试上限、监控鉴权与脱敏；使用本地假模型，不调用真实服务、不创建真实扫描。
7. 本地 Docker 完整构建及隔离冒烟通过后，通过局域网传镜像到 NAS；只重建应用与 Worker 服务，不在 NAS 构建，不重启 Caddy。

## 明确不做

- 不接入服务商账单 API，不声称能追溯本次历史费用的精确来源。
- 不改扫描评分、规则判断、报告评分或管理员/访客角色模型。
- 不自动恢复任何取消批次；只有管理员显式开始或恢复符合当前扫描/配置快照的任务才会产生新请求。
